TypeQuery vs Query
ex) TypedQuery<Member> typedQuery = entityManager.createQuery("select m from Member m", Member.class);
-> 2번째 파라미터로 반환되는 응답 데이터 타입이 명시되어 있거나 확연히 알 때에는 TypeQuery를 사용

ex) Query query = entityManager.createQuery("select m.username, m.age from Member m");
-> m.username은 String 타입이고 m.age는 int 타입이다. 즉 반환되는 값의 데이터 타입이 서로 다르기 때문에 JPA 입장에서는 대서 어떤 데이터 타입으로 반환해야 할 지 모른다 
그럴 때에는 Query를 사용한다. 
만약에  entityManager.createQuery("select m.username from Member m")처럼 타입이 하나인 경우에는 
TypedQuery<String> = entityManager.createQuery("select m.username from Member m")으로 받을 수가 있다. 왜냐하면 반환 타입이 String 하나이기 때문에 반환되는 데이터 타입을 명확히 
알 수가 있다.



getResultList()  vs getSingleResult()
getSingleReulst의 아래 2경우에는 Exception이 터진다.
1. 결과가 없을 떄  : jakarata.persistence.NoResultException
2. 결과가 2개 이상일 때 : jakarata.persistence.NonUniqueResultException
-> 그래서 getSingleRsult의 경우 반드시 정확히 결과가 1개임이 보장될 때 써야 한다.
참고로, getResultList의 경우 결과가 없어도 Exception이 터지지 않고, 그냥 빈 List를 반환

getSingleResult()의 논란
JPA의 getSingleResult()가 0건을 예외로 보는 것이 너무 엄격하다는 논란이다. 단건 조회에서 0건이 되는 것은 조회 목적에 따라 정상인 케이스가 있다.(ex.예를 들어 회원의 존재 여부를 확인하는 조회)
결과가 2개 이상일 떄 예외가 터지는 건 뭐.. 그나마 이해를 해줄 수가 있는데, 결과과 없어서 예외가 터지는 건 뭐 굳이.. 예외를 터트려야 하나? 하는 논란이 있다고 한다.
그래서 Spring Data JPA에서는 getSingleResult 사용 시 NoResultException 발생 시, null을 반환하도록 try-catch로 내부적으로 만들어 져 있다.
그리고 결과가 2개 이상일 떄 발생하는 NonUnqueReulstException은 스프링이 추상황된 예외를 던진다.
